# Автотесты API

Стек: Python, Pytest, requests.

Проект служит демонстрацией тестирования API, покрывающий методы **GET, POST, PUT, DELETE**. Сценарий тестирования: создание папки, в неё создание файла, копирование файла, его удаление. В сумме будет продемонстировано 4 теста.

```
├── api/disk_client.py   # обёртка над API
├── tests/test_disk.py   # 4 теста
├── conftest.py          # фикстура клиента с токеном
├── pytest.ini
└── requirements.txt
```

## Запуск

1. Зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Получение токена по запросу из [полигона](https://yandex.ru/dev/disk/poligon/). Его нужно сохранить в .env под ключом `YANDEX_DISK_TOKEN`:
3. Запуск тестов:
   ```bash
   pytest -v
   ```

Без токена тесты не падают, а помечаются как `skipped`.

Тесты работают в уникальной папке `/autotests-<hash>` и удаляют её в конце прогона.

# Тест-кейсы

Тестируется публичный REST API Яндекс Диска, `https://cloud-api.yandex.net/v1/disk`.

Имеются позитивные сценарии по функционалу, проверка по коду HTTP-ответа и по содержимому тела.

Тестовые данные динамичны, генерируются на каждый запуск, благодаря чему отсутсвуют конфликты между прогонами.

Все кейсы работают внутри своей рабочей папки. Была создана модульная фикстура, которая удаляет папку после прогона, в том числе при падении тестов.

Ожидаемые коды ответов взяты из документации API.

Так как кейсы зависимы по данным, они выполняются последовательно в пределах одного модуля.

## 4. Тест-кейсы

### TC-01: создание папки и получение её метаинформации
| | |
|---|---|
| Приоритет | высокий |
| Тип | позитивный |
| Методы API | `PUT /resources`, `GET /resources` |
| Предусловия | рабочая папка не существует |
| Шаги | 1. `PUT /resources?path=/autotests-<hash>`<br>2. `GET /resources?path=/autotests-<hash>` |
| Ожидаемый результат | 1. Код `201 Created`.<br>2. Код `200 OK`, в теле `type == "dir"`, путь совпадает с запрошенным |
| Автоматизация | `tests/test_disk.py::test_create_folder__put_get` |

### TC-02: загрузка файла на Диск
| | |
|---|---|
| Приоритет | высокий |
| Тип | позитивный |
| Методы API | `GET /resources/upload`, `PUT <href>`, `GET /resources` |
| Предусловия | TC-01 выполнен успешно (папка существует) |
| Тестовые данные | `path = /autotests-<hash>/note.txt`, `overwrite=true`, содержимое — 20 байт |
| Шаги | 1. Запросить ссылку на загрузчик<br>2. Отправить содержимое файла методом `PUT` по полученному `href`<br>3. Запросить метаинформацию файла |
| Ожидаемый результат | 1. Код `200 OK`, в теле `href` и `method == "PUT"`.<br>2. Код `201 Created` (или `202 Accepted`).<br>3. Код `200 OK`, `type == "file"`, `size` равен размеру отправленных данных |
| Автоматизация | `tests/test_disk.py::test_upload_file__post_put` |

### TC-03: копирование файла
| | |
|---|---|
| Приоритет | средний |
| Тип | позитивный |
| Методы API | `POST /resources/copy`, `GET /resources` |
| Предусловия | TC-02 выполнен успешно (исходный файл существует) |
| Тестовые данные | `from = .../note.txt`, `path = .../note-copy.txt`, `overwrite=true` |
| Шаги | 1. Скопировать файл по новому пути<br>2. Запросить метаинформацию копии |
| Ожидаемый результат | 1. Код `201 Created` (или `202 Accepted` для непустой папки).<br>2. Код `200 OK` — копия доступна по новому пути |
| Автоматизация | `tests/test_disk.py::test_copy_file__post` |

### TC-04: удаление файла
| | |
|---|---|
| Приоритет | высокий |
| Тип | позитивный, проверка граничного состояния |
| Методы API | `DELETE /resources`, `GET /resources` |
| Предусловия | TC-03 выполнен успешно (копия существует) |
| Тестовые данные | `path = .../note-copy.txt`, `permanently=true` |
| Шаги | 1. Удалить файл безвозвратно<br>2. Повторно запросить метаинформацию удалённого файла |
| Ожидаемый результат | 1. Код `204 No Content`, тело отсутствует.<br>2. Код `404 Not Found` — ресурс больше не доступен |
| Постусловия | Фикстура `cleanup` удаляет рабочую папку `/autotests-<hash>` |
| Автоматизация | `tests/test_disk.py::test_delete_file__delete` |

## 6. Критерии начала и завершения тестирования

**Критерии начала:**
- установлены зависимости из `requirements.txt`;
- задан валидный OAuth-токен тестового аккаунта в файле `.env`;

**Критерии завершения:**
- все 4 тест-кейса выполнены и имеют статус `passed`;
- тестовые данные удалены с Диска (рабочая папка не остаётся после прогона).
